# Модель брони

Данные в `src/data/armor.ts`, отображение в `src/components/ArmorDemo.astro`. Блок «Броня» появляется на странице техники автоматически, если её `id` есть в `armorOf`.

Модель качественная. В ней нет толщин, эквивалентов и цифр пробития реальных машин, и добавлять их нельзя: показывается только общая закономерность «какой слой что делает».

## Как добавить броню новой машине

Дописать `id` машины в `armorOf` под подходящей схемой:

| Схема | Кому подходит |
|---|---|
| `steel` | танки первых послевоенных поколений со сплошной стальной бронёй |
| `composite` | танки с комбинированной бронёй без навесной динамической защиты |
| `composite-era` | то же с блоками динамической защиты |
| `modular-aps` | машины с модульной бронёй и комплексом активной защиты |
| `light` | БТР, ранние БМП, плавающие танки, САУ: противопульная и противоосколочная броня |
| `light-addon` | БМП и колёсные машины с навесными модулями, разнесением или решётками |

Выбирать схему по серийной базовой версии машины. Если версии сильно различаются (например, поздняя получила активную защиту), лучше завести отдельную запись техники, чем приписывать всей линейке защиту последней версии.

## Как добавить схему, слой или боеприпас

- **Схема:** запись в `armorSchemes` (`id`, `name`, `text`, `layers` снаружи внутрь) и новый вариант в типе `ArmorSchemeId`. В схеме не больше шести слоёв: иначе разрез не помещается.
- **Слой:** запись в `layerTypes` (`kind`, `name`, `text`, `absorb`, `width`) и вариант в `LayerKind`. Для нового `kind` добавить отрисовку в `drawLayer` и цвет в `FILL` компонента, иначе слой нарисуется как сталь.
- **Боеприпас:** запись в `threats` и вариант в `ThreatId`; затем дописать значение в `absorb` каждого слоя (функция `absorb` принимает значения по порядку угроз).

`absorb` это доля воздействия от 0 до 1, которую гасит слой. Итог считается перемножением остатков по слоям:

- остаток ниже `STOP_BELOW` (0,15): «остановлен» на этом слое;
- остаток в конце ниже `EDGE_BELOW` (0,35): «на пределе»;
- иначе «пробитие».

Значения подбираются так, чтобы итог совпадал с общеизвестными закономерностями, а не с цифрами. После любой правки проверить таблицу исходов: динамическая защита гасит кумулятивный заряд, но не тандемный; сталь не держит ни кумулятивный, ни подкалиберный; лёгкая броня держит только осколки; активная защита перехватывает ракеты и гранаты, но почти не влияет на подкалиберный снаряд.

## Проверка

1. `node scripts/check-data.mjs`: строка «Бронетехника без модели брони» должна показывать 0, ошибок связности нет.
2. `npm run build` без ошибок.
3. Открыть `/equipment/<id>/#armor`: переключение боеприпасов запускает анимацию, итог меняется, нажатие на слой на схеме и в списке показывает его описание, кнопка «Повторить» работает.
4. При `prefers-reduced-motion` показывается конечный кадр без анимации.
5. В текстах нет длинного тире, апострофов и цифр пробития.
